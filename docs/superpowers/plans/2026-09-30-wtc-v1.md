# wtc v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `wtc` CLI + `@wtc/lib` + container `kit/` + `examples/setup-basic` + doc deliverables, per the spec.

**Architecture:** Bun/TypeScript monorepo. `@wtc/lib` owns all logic behind a `Runtime` interface (docker CLI impl + `FakeRuntime` for unit tests). `@wtc/cli` is a thin commander wrapper. The container side is bash scripts plus one Go static binary `wtc-kit` (socks / forward / status), mounted read-only at `/wtc/bin`. Host ↔ container communicate only through bind-mounted files (`status.json`, logs).

**Tech Stack:** Bun 1.3 (runtime, test, workspaces, `bun build --compile`), TypeScript strict, zod 3, commander 12; Go 1.25 (kit, stdlib only); docker CLI 29 via colima 0.10 (dev) / Linux docker (CI).

**Spec:** `docs/superpowers/specs/2026-09-30-wtc-design.md` — every task implicitly includes the spec section it cites. Read the cited sections before starting.

## Global Constraints

- **Keep it simple**: small-team internal tool. No security hardening beyond what the spec states; prefer the simplest working implementation.

- Ids (setupId, instance name, volume name): `^[a-z0-9]+(-[a-z0-9]+)*$`.
- Names: container `wtc-<setupId>--<name>`; image `wtc-<setupId>:<imageHash>`; pnpm volume `wtc-<setupId>.pnpm`; setup volume `wtc-<setupId>.v.<vol>`; instance volume `wtc-<setupId>--<name>.v.<vol>`.
- Labels: `wtc.setup`, `wtc.setupDir`, `wtc.name`, `wtc.protocol` (= `1`), `wtc.socksHostPort`, volumes also `wtc.scope`.
- Create flags always: `--init`, `--restart unless-stopped`, `-p <socksBind>:<socksHostPort>:<socksPort>`, entrypoint `/wtc/bin/wtc-entry`.
- Defaults: `socksPort 1080`, `socksBind "0.0.0.0"`, `socksHostPortRange [21080, 21179]`, `readyTimeout 900` (seconds), `image.context "image"`, `image.dockerfile "Dockerfile"` (relative to context), `init "init.sh"`, `cwd "/workspace"`, check `timeout 10` (seconds).
- Container mounts (§6.1): `/pnpm` rw, `/wtc/bin` ro (kit), `/wtc/setup` ro, `/wtc/ssh` ro, `/wtc/ssh-agent.sock`, `/wtc/run` rw, `/wtc/log` rw.
- State dir: `<setup>/.wtc/run/<name>/` (status.json, create.json, ssh/), `<setup>/.wtc/log/<name>/init.<bootId>.log`.
- Kit cache: `~/.cache/wtc/kit/<wtcVersion>/` (override with env `WTC_CACHE_DIR`).
- pnpm env: `PNPM_CONFIG_STORE_DIR=/pnpm/store`, `PNPM_CONFIG_CACHE_DIR=/pnpm/cache`; pnpm ≥ 11.23 → `PNPM_CONFIG_VIRTUAL_STORE_TYPE=global`, else `PNPM_CONFIG_ENABLE_GLOBAL_VIRTUAL_STORE=true`.
- Lock: `/pnpm/.wtc-lock` — `wtc-install` takes `flock -s`, `gc --prune-store` takes `flock -x`.
- CLI has zero business logic; every query command supports `--json`.
- No runtime dependencies beyond `zod` and `commander`. Go kit: stdlib only.
- Every bind source on colima must live under `$HOME` (colima silently mounts an empty dir otherwise) — tests that bind-mount must use dirs under `$HOME`, never `/tmp`.
- Integration tests run only when `WTC_INTEGRATION=1`; resources they create use setupId prefix `wtcit` and must be cleaned up in `afterAll`.

## Review Focus

- **Host http(s)_proxy / NO_PROXY in env**: the dev machine exports `http_proxy`; any host-side curl/fetch used by tests or `doctor` must not route through it. `wtc tunnel` hint must mention unsetting localhost bypass. Test: tunnel output contains `socks5h://` and a NO_PROXY warning (Task 8).
- **Instance re-`up` with no `--set`**: must not report a params mismatch just because defaults were applied at create time. Test in Task 6.
- **init.sh missing / not executable**: entry must mark `failed` with a clear message, not hang in `booting`. Test in Task 4.
- **Socks port already taken by a non-wtc process on first up**: must retry next port, not fail. Test (FakeRuntime start throws "port is already allocated") in Task 6.
- **`rm` of a `stopped` instance without `--force`**: must refuse with a hint (preRemove needs a running container); `--force` works in any state. Test in Task 6.

### Task 4: Container kit — Go `wtc-kit` + bash scripts (spec §6, §7)

**Files:** `kit/go/{go.mod,main.go,socks.go,forward.go,status.go,*_test.go}`, `kit/bin/{wtc-entry,wtc-signal,wtc-install}`, `kit/build.sh`, `kit/test/entry.test.ts`, `packages/lib/src/kit/embed.ts`, `packages/lib/test/kit/embed.test.ts`.

**`wtc-kit` subcommands:**
- `wtc-kit socks --listen 0.0.0.0:1080 [--user U --pass P]` — SOCKS5 CONNECT (RFC 1928), address types IPv4/domain/IPv6, auth methods 0x00 or 0x02 (RFC 1929) — when user set, only 0x02 accepted.
- `wtc-kit forward --listen 127.0.0.1:3306 --to host.docker.internal:3306` (repeatable pairs via multiple invocations).
- `wtc-kit status init --file F --boot-id ID` → writes `{bootId, startedAt: now ISO (UTC, ms), state:"booting", phase:null, history:[{at,state:"booting"}]}`.
- `wtc-kit status phase --file F --name N [--message M]` — only if state==booting; appends history.
- `wtc-kit status finish --file F --state ready|failed [--exit-code N] [--reason exit|timeout] [--message M]`.
- All writes atomic: write `F.tmp.<pid>` then rename. Also print one line `[wtc] phase <name> <msg>` to stdout.

**Bash (`#!/usr/bin/env bash`, `set -euo pipefail`), paths overridable by env for host-side tests:** `WTC_BIN=/wtc/bin`, `WTC_RUN=/wtc/run`, `WTC_LOG=/wtc/log`, `WTC_SETUP_MOUNT=/wtc/setup`, `WTC_SSH=/wtc/ssh`.
- `wtc-signal phase <name> [msg]` → `wtc-kit status phase`.
- `wtc-install [pnpm args…]` → `wtc-signal phase install`; `cd "$WTC_CWD"` unless args include `-C`; `flock -s /pnpm/.wtc-lock pnpm install --frozen-lockfile --prefer-offline "$@"`.
- `wtc-entry`:
  1. `bootId=$(date -u +%Y%m%dT%H%M%S)-$RANDOM`; `wtc-kit status init`.
  2. copy `$WTC_SSH/{config,known_hosts}` into `~/.ssh` (mkdir -p, chmod 700/600) if present; export `SSH_AUTH_SOCK=/wtc/ssh-agent.sock` if it exists.
  3. export pnpm env per Global Constraints (detect via `pnpm --version`, compare semver ≥ 11.23; missing pnpm → skip). Also `PATH=/wtc/bin:$PATH`.
  4. background `wtc-kit socks` (with `WTC_SOCKS_USER/PASS` if set) and one `wtc-kit forward` per `WTC_HOST_FORWARDS` entry.
  5. run `$WTC_SETUP_MOUNT/$WTC_INIT` in its own process group (`setsid`), stdout/stderr `tee -a` to `$WTC_LOG/init.$bootId.log`; enforce `WTC_READY_TIMEOUT` seconds (kill the group with TERM then KILL after 5s) → `finish failed --reason timeout`; exit 0 → `finish ready`; non-zero → `finish failed --exit-code N --reason exit`; missing/non-executable init → `finish failed --message "init script not found or not executable: <path>"`.
  6. stay resident: `trap` TERM/INT → kill children, exit 0; `wait` loop (`sleep infinity & wait`).
- `kit/build.sh`: `cd kit/go && for a in amd64 arm64; do CGO_ENABLED=0 GOOS=linux GOARCH=$a go build -trimpath -ldflags='-s -w' -o ../dist/linux-$a/wtc-kit .; done`. Root script `"build:kit": "bash kit/build.sh"`, and `test`/`build` depend on it.
